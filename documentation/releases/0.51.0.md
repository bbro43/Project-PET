# 0.51.0 — Folder leftovers: sorting, the game's cursor and count box, Tag chips

## Sorting (rom-verified)
- **Start** opens the game's SORT window. A sorts; B or Start closes it. On a keyboard, Start is Enter.
- The seven orders are the game's: ID, ABCDE, Code, Attack, Element, No., MB.
- Keys come from the list entries built by sub_811FCB8:
  - ID: id_sort_pos (chip data +0x1C);
  - ABCDE: alphabet_sort_pos (+0x18);
  - Code: the code itself;
  - Attack (sub_811FF80): flag 0x10 counts as 1, flag 2 uses the power, anything else counts as 5; power codes 1001–1018 (Navi SP chips) use their first tier from 0x20E54;
  - Element (byte_811FF60): fire, aqua, elec, wood, sword, wind, cursor, obstacle, plus, break, none;
  - No.: the number of copies of that chip and code;
  - MB.
- Ties fall back to chip, then code, and stay in ascending order even when the key sorts descending.
- Direction: the first time you pick an order it uses byte_30069A0[mode] ^ 4, so Attack and No. go high to low and the rest go low to high. Picking the same order again reverses it (0x81347F8). The sorts themselves are sub_30069A8 (ascending) and sub_3006A5E (descending).
- The Pack opens in chip order (key 7), as in the game. Sorting the folder keeps the Regular and Tag chips with their chips.
- data/bn6-chips.mjs now also carries `abc`, `order` and `tiers` (the 11 power tiers of the Navi SP chips) per chip, read from the ROM by tools/extract_bn6_chips.py.

## The game's cursor, page arrows, scroll thumb and count box (rom-verified)
- **Cursor:** byte_81331F4, OBJ tiles 0x240 / 0x244 / 0x248 (16×16, palette 12), 6 frames each. It sits at x 90 on the folder page and x 0 on the Pack, y 32 + 16·row.
- **Page arrows:** byte_81331EC, tiles 0x250 / 0x24F / 0x24E. One at x 231 on the folder page; a flipped one at the Pack's left edge.
- **Scroll thumb:** tile 0xC24C, 8×16. x 226 (folder) / 146 (Pack), y 28 + top·100 / (count − 7). Hidden when the list fits on one screen.
- **Count box:** the 30/30 box is object type 0xD (sub_8117BE8), Folder Edit blob 0x2034B6C, last frame of its opening, at (212,12). It is empty on the Pack, because the app's Pack has no chip count.

## Tag chips
- **Select** now opens a Regular / Tag choice, as the game does (text script 0xA). The Regular works as in 0.50.0.
- **Tag:** pick two folder chips; the first waits for the second. Rules from sub_81349E8 / sub_8133D64:
  - together they may total at most 60 MB (0x3C);
  - the Regular can't be tagged, and a tagged chip can't be the Regular.
  - Tag again on a tagged chip clears the pair.
  - The message wording is the app's own.
- The game's TAG frame (blob 0x203526C, sequence 1) is drawn round both chips. Each folder keeps its own pair (Navi stats 0x56 / 0x57 + 2·folder in the game).
- **In battle** (sub_800A318 / sub_800A570, rom-verified): the pair is swapped to slots 28 / 29 and left out of the shuffle. After the GigaChips are placed, the pair moves to positions k, k + 1 with k = 1 + rnd % 19. So tagged chips always come in together, never in the Regular's slot.
- **Not yet traced:** how the custom screen treats a tagged pair (the hand keeps a tag byte per slot at +0x44). Selection still follows the normal code rules.
- **Simplification:** if a Regular is set, the app keeps the tag pointing at the same chips after the Regular is swapped to the front. The game swaps the saved slot numbers as they are.

## Not modelled
- A folder rule for chips with flag 0x20 (at most 3, sub_8135080) exists in the code, but no BN6 chip has that flag, so it is left out.
